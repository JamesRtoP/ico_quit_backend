# MedApp API contract

Machine-readable contract: [`openapi.json`](openapi.json) (OpenAPI 3.1). A test snapshots it, so any contract change shows up in the PR diff. To regenerate after an intended change:

```bash
UPDATE_OPENAPI_SNAPSHOT=1 dotnet test api --filter "FullyQualifiedName~Contract_MatchesSnapshot"
```

The document is generated by the test suite, not served by the running API (there is no Swagger UI). Hand `openapi.json` to the chatbot team: Azure AI Foundry imports it as an OpenAPI tool, and the endpoint summaries tell the model what each endpoint is for.

## Callers

| Caller | Token | Endpoints |
|---|---|---|
| Patient mobile app | The patient's own Microsoft Entra External ID token | `/user/*` (none yet) |
| Client's Foundry chatbot | A delegated **on-behalf-of** token: the patient's identity (`oid`), issued to the chatbot app (`azp`/`appid` = the chatbot's client id) | `/chatbot/*` |

In both cases the API takes the patient from the token's `oid` and resolves it to their FHIR Patient. **No endpoint accepts a patient id**: any `patientId`, `userId`, `subject` or `patient` sent in a query string or body is ignored. The chatbot (and its model) can therefore only reach the patient who is chatting.

Medications and doses are not currently supported.

## Conventions

- **Auth:** every endpoint except `/status` needs `Authorization: Bearer <access token>`. The chatbot's Foundry tool should attach the token itself, outside the model's context.
- **JSON:** camelCase.
- **Errors:** [RFC 9457 problem details](https://www.rfc-editor.org/rfc/rfc9457) with a generic `title` and a `traceId`. Error responses never echo request data.

| Status | Meaning |
|---|---|
| 400 | Validation failed (`errors` lists the field names) |
| 401 | Token missing, expired or invalid |
| 403 | Token is valid but not allowed: its `oid` isn't linked to exactly one Patient, or (for `/chatbot`) it wasn't issued to the chatbot app |
| 501 | Endpoint is a stub: auth and input passed, but it isn't implemented yet |
| 502 / 503 | FHIR backend error / unavailable. Safe to retry 503 |

## Endpoints

### `GET /status`
Anonymous. `200` with an empty body. Returns no data.

### `GET /chatbot/context` (stub)
**Intent:** the chatbot asks for the FHIR information it needs about the signed-in patient to answer them. What it returns is not decided yet.

Today: `501` once auth passes. It reads no patient data beyond the token → Patient lookup.

### `POST /chatbot/responses` (stub)
**Intent:** the chatbot submits the response it gave the signed-in patient, to be stored (for example as a FHIR `Communication` with `subject` set server-side).

```json
{ "text": "..." }
```

- `text` (required): 1 to 4000 characters. It may contain PHI, so it is never logged.

Today: `400` on invalid input, otherwise `501`. Nothing is stored.
